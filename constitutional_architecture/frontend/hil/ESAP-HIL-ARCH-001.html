Architecture Decision Record

ESAP-HIL-ARCH-001 — Human Interaction Layer Projection Engine

Four ratified architecture decisions for the Phase 16 Human Interaction Layer (HIL): capability-based navigation projection, immutable ISR snapshots, constitutional arbitration, and a renderer-agnostic UI Projection Model.

status RATIFIED phase 16 authority architecture board doctrine ISR sole source of truth

D-1Capability-based navigation projectionratified

The navigation tree and every interactive affordance are a projection of the capability ledger — never hand-authored screen state. Projection is deny-by-default: a surface is shown only when the principal holds the governing capability, and every denial is explainable.

Binding rules

  • Ledger lives in the ISR Governance chromosome (CKB-owned); projection consumes it, never mutates it.
  • Deny-by-default; a missing capability yields denial(cap, principal, reason) with reason = requires <cap>.
  • Capability changes are additive migrations: deprecate(old) + introduce(new) with a compatibility window during which both claims are emitted.

D-2Immutable ISR snapshotsratified

The UI renders from a live working ISR; every phase-commit publishes an immutable, content-addressed snapshot. Diffing is semantic — per chromosome family over the ISR graph — never textual.

Snapshot contents

  • ISR graph (nodes + typed edges), genome state, fitness vector, telemetry reference.
  • Addressed by content hash: snapshot_id = hash(isr_graph, genome, fitness, telemetry_ref).
  • Diff deltas are per-family: arch / be / per / msg / inf / sec / obs.

D-3Constitutional arbitrationratified

Conflicts between humans, coordinator, and agents resolve through a total-order priority stack, not consensus votes.

# priority stack (highest first)
Constitution > safety guards > humans > coordinator > agents
  • Every arbitration is machine-checkable: a predicate over inputs, constitution rules, and safety guards.
  • Arbitration records are append-only and hash-chained; each record is re-derivable from inputs + predicates (deterministic replay).
  • Human-absent escalation: standing policies ratified once as arbitration records (priority-3 equivalent), bounded timebox, park at last checkpoint on timeout.

D-4Renderer-agnostic UI Projection Modelratified

The UIPM is a versioned, renderer-independent intermediate representation compiled to concrete renderers. React is the first compiler backend (P0); Terminal (P1), Desktop/Mobile (P2), AR/VR (P3) follow.

UIPM v1 surfaces

  • navigation · capability-keyed tree  layout · panels, docks, maps  components · cards, tables, gauges  commands · promote, mutate, run  events · telemetry, log, arbitration notices
  • Latency budgets: navigation ≤ 16ms, layout ≤ 100ms.
  • Renderer equivalence is a test property: identical capability + command surfaces across backends.
  • UIPM is a derived projection, never stored: projection_ref = hash(isr_snapshot, principal, capability_schema_ver, uipm_ver); replay re-derives. Renderer ephemeral state (scroll, focus) is explicitly excluded.

RResolutions & ownershipbound

Governance chromosome

CKB owns the capability schema. Renames are deprecate(old)+introduce(new) (additive, compatibility window, both claims emitted) — precedent: compiler VERSION/consumed_genes scoping. Note: core/models/genome.py currently carries 14 categorical + 7 continuous genes with no governance family — to be added.

Merge semantics

Semantic three-way merge over the ISR graph with LCA base: non-overlapping families auto-merge; same-family conflicts resolve by empirical fitness dominance (Phase 18 calculator) with a mandatory arbitration record. Lineage is a DAG: result has parents: [branch, working].

Escalation timebox

Convergence required within the bounded timebox, else Phase 18 convergence criteria reuse (8h); on timeout the system parks at the last checkpoint. Gate re-used: MutationDirective.max_severity.
