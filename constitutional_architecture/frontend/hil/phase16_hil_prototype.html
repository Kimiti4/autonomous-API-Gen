Human Interaction Layer — Specification

Design system, navigation architecture, component library, accessibility and motion standards, and the frontend architecture that keeps every screen an ISR projection.

16.0Design Principles

Five principles govern every screen. They are direct UI translations of the platform Constitution.

P-01
ISR-first

Every workflow maps back to the Intermediate Software Representation. Screens never own architectural truth.

P-02
Context-aware

Navigation shows only tools relevant to the current engineering task and project depth.

P-03
Progressive disclosure

Advanced capability surfaces as users drill deeper — beginners safe, experts unhindered.

P-04
Workspace-centric

Users inhabit projects, not isolated pages. State, breadcrumbs and panels persist per workspace.

P-05
Live architecture

Diagrams, code, metrics and evolution stay synchronized through one telemetry bus.

16.6Accessibility Standards

WCAG 2.2 AA is the floor, not the goal. Telemetry is dense — accessibility keeps it legible for everyone.

Contrast ≥ 4.5:1 for body text in both themes; signal hues carry dark-variant pairs.
Full keyboard operability — palette, tree, graph and dock reachable without a pointer.
prefers-reduced-motion disables the ambient canvas and long animations.
Every visualization ships a semantic alternative: tables for charts, ARIA labels for graphs.
Focus-visible rings everywhere; never removed for aesthetics.
Telemetry regions use polite live-regions; high-frequency streams are announced off.
16.7Frontend Architecture — UI as ISR Projection

The renderer itself obeys the Constitution: React, Svelte or a terminal UI are all just compiler backends over the same ISR view-model. Components contain no architectural logic.

Binding rules
▸ One ISR subscription per workspace. Views never fetch architectural state independently.
▸ Views are pure projections. Mutations only via registered commands — the same commands agents issue.
▸ Dock panels are plugins. Inspector, Docs and Copilot register through the panel API; Phase 17+ plugins reuse it.
▸ Tokens are the theming contract. Per-workspace overrides touch tokens only, never component code.
▸ Renderer is a backend. Swapping React for another renderer must require zero evolution-engine changes.
Architectural Decision Records
ADR-016-1UI as ISR projection, not screen-local state
ContextEvery screen must stay synchronized with an architecture that evolves autonomously in the background.
DecisionViews are pure functions of ISR + telemetry streams; all mutations flow through the command bus.
Trade-offsRequires a robust event bus and normalized cache before renderer work; gains zero state drift and renderer swappability.
ADR-016-2Workspace-centric navigation over a flat sitemap
ContextThe platform spans 15 phases of capability; a flat menu would overwhelm beginners and slow experts.
DecisionNavigation is projected from context (workspace → project → depth), compensated by breadcrumbs and a global palette.
Trade-offsDiscoverability depends on search quality; gains progressive disclosure without hiding capability.
ADR-016-3Color tokens derived from chromosome families
ContextUsers must read architectural semantics at a glance across diagrams, chips, graphs and logs.
DecisionEach chromosome family owns one hue, consistent across every module; surfaces remain neutral.
Trade-offsDiscipline required — no ad-hoc colors; gains instant cross-view literacy and a built-in legend language.
