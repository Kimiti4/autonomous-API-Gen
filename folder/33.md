# The most important new property: attack independence

Given what happened with Campaign D in Phase 31, Phase 33 should explicitly prevent:

```text
expected outcome
       ↓
attack selection
```

Instead:

```text
ISR / artifact
       ↓
attack surface
       ↓
applicability
       ↓
attack selection
       ↓
execution
       ↓
observed outcome
```

The attack engine must not know whether a target is supposed to pass or fail.

For deliberately vulnerable discrimination artifacts, the vulnerability label must be kept outside the execution subject and revealed only during evaluation.

That gives you:

> **Security-certifier sensitivity without tautological attack construction.**

# What "senior engineer level" should mean

I would **not** define senior-level security certification as "passes OWASP."

That is too weak.

For Tiannara, senior-level certification should mean the system has demonstrated all of these:

```text
1. It knows what security surfaces exist.

2. It knows which attacks apply.

3. It can execute those attacks safely.

4. It produces reproducible attack evidence.

5. It distinguishes blocked, detected, contained, missed and bounded.

6. It detects deliberately introduced vulnerabilities.

7. It does not falsely certify vulnerable artifacts.

8. It does not depend on generator provenance.

9. It tests human-engineered baselines.

10. It exercises difficult/adversarial architectures.

11. It measures detection and recovery, not merely scanner findings.

12. It preserves causal evidence.

13. It remembers historical failures.

14. It feeds failures back into ISR evolution.

15. It never changes the rules because the artifacts fail.

16. It refuses certification when evidence is incomplete.

17. It can survive a campaign specifically designed to break its certifier.
```

That is a much stronger claim than:

> "Tiannara runs security scanners."
